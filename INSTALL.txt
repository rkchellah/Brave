# QuantifyX — Installation Guide

---

## Prerequisites

- Python 3.9+
- Git
- Windows PowerShell (dev environment)
- Kraken account (kraken.com)
- PRISM account (prismapi.ai)
- Firebase account (console.firebase.google.com)

---

## Step 1 — Clone the Repository

```powershell
git clone https://github.com/rkchellah/QuantifyX.git
cd QuantifyX
```

---

## Step 2 — Create Virtual Environment

```powershell
python -m venv .venv
```

Activate it:

```powershell
& ".\\.venv\\Scripts\\Activate.ps1"
```

You should see `(.venv)` at the start of your prompt.

**Important:** Always use the explicit python path when running scripts to avoid
resolving to a wrong venv:

```powershell
& ".\.venv\Scripts\python.exe" your_script.py
```

---

## Step 3 — Install Dependencies

Always install using the explicit python path:

```powershell
& ".\.venv\Scripts\python.exe" -m pip install krakenex python-dotenv numpy requests firebase-admin
```

Verify:

```powershell
& ".\.venv\Scripts\python.exe" -c "import krakenex; print('krakenex ready')"
```

---

## Step 4 — Get API Keys

### Kraken

1. Log into kraken.com
2. Go to Security → API → Add Key
3. Create **QuantifyX-Agent** key with these permissions:
   - ✅ Query Funds
   - ✅ Query Open Orders & Trades
   - ✅ Query Closed Orders & Trades
   - ✅ Create & Modify Orders
   - ✅ Cancel & Close Orders
   - ❌ Withdraw (never)
4. Create **QuantifyX-Leaderboard** key (read-only):
   - ✅ Query Funds
   - ✅ Query Open Orders & Trades
   - ❌ Everything else
5. Copy both keys immediately — the secret is only shown once

### PRISM

1. Sign up at prismapi.ai
2. Redeem code: `LABLAB` (gives $10 free credits)
3. Create API key — starts with `prism_sk_`

### Firebase

1. Go to console.firebase.google.com
2. Create project `quantifyx`
3. Enable Realtime Database
4. Go to Project Settings → Service Accounts → Generate New Private Key
5. Save as `serviceAccountKey.json` in the project root

---

## Step 5 — Configure Environment

Create `.env` in the project root:

```
KRAKEN_API_KEY=your_quantifyx_agent_key_here
KRAKEN_API_SECRET=your_quantifyx_agent_secret_here
PRISM_API_KEY=your_prism_key_here
```

Never commit this file. It is already in `.gitignore`.

```powershell
& ".\.venv\Scripts\python.exe" test_frost.py
```

Expected output (during Asian session):

## Step 9 — Run the Agent

```powershell
& ".\.venv\Scripts\python.exe" src/agent.py
```

The agent runs every 15 minutes. It will only generate signals during Asian session (00:00–06:00 UTC).

## Troubleshooting

**`ModuleNotFoundError: No module named 'krakenex'`**
The package installed into the wrong venv. Fix:
```powershell
& ".\.venv\Scripts\python.exe" -m pip install krakenex
```

**`ModuleNotFoundError: No module named 'dotenv'`**
Same issue. Fix:
```powershell
& ".\.venv\Scripts\python.exe" -m pip install python-dotenv
```

**`Exception: Either key or secret is not set`**
Your `.env` file is empty or the keys are not filled in.
Check: `Get-Content .env`
Open and paste your actual keys: `code .env`

**`No signal — Outside Asian session`**
This is correct behavior. Frost only trades 00:00–06:00 UTC.
To test during the day, use backtest mode in `test_frost.py`:
```python
signal = f.analyze('XBTUSD', provided_rates={'M15': candles})
```

**`ATR too high — volatile`**
BTC is moving too fast right now. The agent will trade when ATR drops during
the calm Asian session. No action needed.

**`Kraken CLI install fails on Windows`**
Kraken CLI v0.3.0 has no Windows binary. QuantifyX uses `krakenex` instead.
Do not attempt to install the CLI on Windows. See ARCHITECTURE.md for details.

**`sh is not recognized`**
You are using PowerShell. The Kraken CLI install script requires bash.
QuantifyX does not use Kraken CLI — ignore this.

**PowerShell venv activation error**
If activation fails, run this once to allow scripts:
```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

## Notes on Company Laptop

- Do not install WSL on a company laptop without IT approval
- Do not enable developer mode without IT approval
- `krakenex` works entirely within Python — no system-level changes needed
- All API calls are outbound HTTPS — no firewall issues expected
